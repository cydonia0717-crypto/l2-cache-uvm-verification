# Address Mapping and Memory-Tag Notes

This note records the mapping used by the pinned Vortex cache configuration in this project.

## Cache geometry

- capacity: 256 KiB
- 4 banks
- 4 ways
- 64-byte line
- 64-bit / 8-byte core word

Per bank, capacity is 64 KiB. `64 KiB / (64 B × 4 ways) = 256 sets`, so each bank has an 8-bit set index.

## Byte-address decomposition

With an 8-byte word, 64-byte line and four banks, the byte address decomposes as:

`[63:16] tag | [15:8] set | [7:6] bank | [5:3] word-in-line | [2:0] byte-in-word`

For the aligned 64-bit core transactions generated by this TB, bits [2:0] are zero; partial stores use the 8-bit byte-enable.

Therefore:

- byte [5:3] selects one of eight 64-bit words in a 64-byte line;
- byte [7:6] selects bank 0–3;
- byte [15:8] selects one of 256 sets inside that bank;
- byte [63:16] is the tag for the current 64-bit build.

Consecutive 64-byte lines rotate across banks. Addresses separated by 256 bytes keep the same bank and move to the next set. Addresses separated by 64 KiB keep the same bank and same set but change the tag, which is useful for controlled 4-way conflict/replacement tests.

## MSHR-full address construction

MSHR size is eight per bank. A correct MSHR-full test therefore generates nine independent misses that map to one bank. Spreading them over banks would test aggregate concurrency instead of the bank-local resource limit.

The separate global-pressure case distributes misses across all four banks and reaches 32 aggregate outstanding entries.

## External memory tag

The CI build defines `NDEBUG`, so Vortex uses `UUID_WIDTH=1`.

For this project:

- MSHR id width = log2(8) = 3 bits
- bank arbitration width = log2(4/1) = 2 bits
- UUID width = 1 bit
- external memory tag width = 6 bits

At a bank, the request tag is `{UUID, MSHR_ID}`. Because four banks share one memory port, the outer request crossbar appends the two bank-routing bits, so the memory-side tag is effectively `{UUID, MSHR_ID, BANK_ARB}`.

On a refill, the low routing bits select the bank and the bank-local tag selects the MSHR. This is why the memory model can return refills out of request order as long as it returns the original tag unchanged.

## Interview-safe explanation

> 每个 miss 在 Bank 内由 MSHR ID 跟踪，Memory Request 的 tag 会带上 MSHR 上下文；4 个 Bank 共用一个 Memory Port 时，外层还会附加 Bank 路由信息。Memory Agent 可以把 response 顺序打乱，但必须原样带回 tag，DUT 再先路由到对应 Bank，然后定位到对应 MSHR，所以不同 miss 的 refill 不依赖返回顺序。
